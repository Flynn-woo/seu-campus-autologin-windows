# 公开版自动启动修复说明

## 问题与原因

用户反馈：手动测试能够登录，但重启或网络重连后不会自动登录。

对 0.1.0 源码的检查确认：

1. 正式任务只有 Windows 登录触发器，没有网络重连或睡眠唤醒触发器，也没有后续补查。
2. 任务注册失败后的启动项仍只运行一次，不能处理登录后才接通网络或中途掉线。
3. 认证重试错误地共用“等待网关就绪”的截止时间；慢启动或零等待测试会取消第二次技术性尝试。
4. 提交后的成功判定仅检查外部站点，未及时识别网关已认证的结果页。

前两项直接解释“手动成功、自动不工作”的反馈。由于没有对方电脑的日志，无法确认其具体走了哪种安装路径。

## 修复后的行为

- 任务计划包含登录、网络接通、睡眠唤醒和每两分钟补查四个触发器。
- 事件注册受限时保留登录和周期任务；整个任务计划不可用时，启动项持续监测。
- 任务使用当前 Windows 交互用户的普通权限；电池模式可以运行；不要求管理员账户；重启后需要登录安装时使用的账户。
- 公开版使用独立无窗口入口，自动失败时不弹出浏览器。每次认证最多两次技术性尝试。
- 明确拒绝认证后写入不含凭据的暂停标记，后续后台事件不再提交；重新配置凭据后恢复。
- 覆盖安装默认保留公开版凭据；更新任务和程序，删除旧启动项，结束旧公开版进程。
- 测试入口显示实际任务状态并生成脱敏 JSON，便于判断是否未触发、已禁用、程序丢失或认证被拒绝。

## 验证范围

69 项 Python 回归测试通过，覆盖率为 84.75%，达到仓库 80% 门槛；Ruff 和差异检查通过。Windows PowerShell 5.1 和 PowerShell 7 安装逻辑验证通过，覆盖完整触发器、事件权限不足回退、任务计划不可用回退、电池设置、重复启动项清理及错误凭据暂停。

构建并检查免 Python 的 Windows x64 程序；无窗口入口专门覆盖了 Python 3.10 标准输出为空导致版本检查异常的问题。

实际创建带随机名称的临时 Windows 任务，保存了四个触发器；由系统启动无窗口程序返回 0，随后观测到两分钟定时自动执行也返回 0。任务动作仅运行 `--version`，测试结束后已删除临时任务。

真实打包程序的已联网后台检查返回 0；只读门户检查识别为已认证。Windows PE 子系统检查确认前台为控制台程序、后台为无窗口程序。ZIP 完整性及不包含本地日志、诊断报告、暂停标记的检查通过。

启动项备用模式使用真实无窗口 `watch` 程序连续完成两次在线检查，第二个实例自动退出；测试进程已全部停止。

构建使用本机 `torch_codex`。共享开发环境存在可选 `chardet` 版本警告，测试通过；发布包已排除该可选依赖，使用 `charset_normalizer`，打包程序运行没有该警告。

尚未在对方电脑上进行真实重启、断线重连或睡眠唤醒试验；本机验证不代表对方机器的系统策略、杀毒设置和校园网环境已得到验证。
